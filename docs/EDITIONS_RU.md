# Три приложения из одного проекта

Исходный вариант публикуется в корне сайта, вариант с помощником по регламенту —
в подпапке `reglament/`, вариант без помощника — в `bez/`. GitHub Actions собирает и проверяет все три приложения
одним запуском. Отдельный репозиторий или ручная сборка не требуются.

| Вариант | Адрес | Название при установке |
| --- | --- | --- |
| Исходный помощник | https://kkmusa.github.io/sanich6-ios-pwa/ | Оператор ДНГ |
| Помощник по регламенту | https://kkmusa.github.io/sanich6-ios-pwa/reglament/ | Опер ДНГ рег |
| Без аварийных остановок | https://kkmusa.github.io/sanich6-ios-pwa/bez/ | Опер ДНГ без |

Второй вариант отличается текстами 12 разделов помощника. Расчётные функции,
ввод данных, история, ВНР, инструкции станций и фотографии собираются из общих
исходников. Сборка проверяет побайтовое совпадение математического модуля.

В четырёх разделах версии «рег» сначала показан прежний авторский «Порядок
работы», ниже — «Требования регламента»: запуск ВНР, замер давления ППД,
остановка водовода зимой и промывка. Другие восемь разделов содержат только
документальный текст. Авторские дополнения автоматически извлекаются из
первой версии при сборке; отдельная ручная копия в исходниках не ведётся.

## Как не перепутать версии

На главном экране второго варианта есть надпись «Опер ДНГ рег»; в разделе
«О приложении» — подпись «Инструкции по регламенту». На домашнем экране
телефона его ярлык называется «Опер ДНГ рег». Исходный вариант остаётся по прежнему адресу.

История расчётов, запущенный секундомер, черновики форм, закладки ВНР, положение
чтения, отметки загрузки и кэши разделены. Очистка истории или сброс замера в
одном приложении не изменяет данные другого. При этом все три приложения используют
место одного сайта, поэтому очистка всех данных сайта средствами браузера
удаляет данные всех вариантов.

В каждом приложении нужно отдельно загрузить страницы ВНР и фотографии для
работы без сети. Это позволяет сохранять и обновлять каждую копию независимо.

## Где править код

- Общие расчёты: `js/math.js`.
- Исходный помощник: `assistantTopics` в `js/reference-data.js`.
- Помощник по регламенту: `js/assistant-reglament-data.js`.
- Выбор четырёх авторских дополнений: `authorAdditions` в
  `scripts/assistant-validation.mjs`; файл `assistant-author-extra.js`
  создаётся только в сборке `reglament` и кэшируется для офлайн-доступа.
- Сборка трёх каталогов и разделение имён хранилищ: `scripts/build.mjs`.
- Проверка трёх приложений на одном адресе сервера: `tests/editions.browser.cjs`.

Документальный помощник подключается только во второй сборке, перед
`reference-data.js`. В интерфейсе отображаются рабочие тексты без служебных
ссылок и комментариев. Привязка выдержек к документам сохранена в материалах
проверки проекта.

Сборка не копирует `dist/` в себя: в `dist/reglament/` попадают только
перечисленные файлы публикации. Пространства имён постоянных данных меняются
только у второй копии; данные ранее установленного исходного приложения
продолжают использовать прежние ключи. Для каждой копии регистрируется свой
service worker с точным путём, а родительский worker исключает запросы второй.

В третьем варианте нет карточки аварийных остановок и нештатных режимов;
тексты помощника не включаются в его сборку. Переход к этому разделу
перенаправляется в справочник. Остальные инструменты доступны.
