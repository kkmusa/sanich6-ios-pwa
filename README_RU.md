# Оператор ДНГ — PWA для Android и iPhone

## Автоматическая публикация без терминала

Для владельца и пользователей: [пошаговая инструкция GitHub Pages и установки на телефон](GITHUB_PAGES_RU.md). Workflow **Publish Operator DNG** проверяет приложение, собирает его и публикует изменения ветки `main`.

Полная статическая версия 3.0.8 с рабочими калькуляторами, справочниками, 207 страницами регламента ВНР и инструкциями пяти станций. Электронный уровень исключён по заданию.

Последние изменения: [версия 3.0.8](CHANGES_V3_0_8_RU.md).

## Запуск для разработки

Для самого приложения нужен Python 3 или другой HTTP-сервер:

```sh
python3 -m http.server 8081 --bind 127.0.0.1
```

Команду выполняйте в корне PWA. Файлы следует открывать через HTTP/HTTPS: Service Worker не работает через file://. HTTPS обязателен при публикации и установке на iPhone; локальный сервер используется только для разработки.

## Проверки и подготовка публикации

Node.js 20+ и Python 3:

```sh
npm ci --ignore-scripts
npm run check
npm test
npm run build
```

Для браузерных тестов требуется Chromium. В подготовленной облачной среде он найден автоматически по `/usr/bin/chromium`. В другой среде выполните `npx playwright install chromium` либо укажите `CHROMIUM_PATH` к своему Chromium. Если песочница запрещает локальные сокеты, запуск HTTP-сервера/Chromium требует разрешённого режима выполнения; это ограничение среды, а не повод отключать проверки. Загрузка браузера требует разрешённых сетевых доменов Playwright. Playwright и инструменты разработки закреплены в package-lock.json.

`npm run check` проверяет JS, manifest, версию оболочки, ссылки на файлы, 207 страниц и их размеры, поисковые данные, материалы станций и базу ПЭД. `npm test` запускает имеющиеся тесты; браузерный набор сам создаёт локальный сервер на свободном порту и завершает его. `npm run build` повторяет проверку и формирует готовый статический каталог `dist/`.

Если Android восстановлен рядом, `python3 scripts/audit-android.py` повторяет проверку исходных материалов. Для повторной JVM-сверки расчётов см. ANDROID_PARITY_RU.md.

## Публикация

Опубликуйте **содержимое `dist/`** на статическом HTTPS-хостинге с сохранением каталогов `js/`, `assets/`, `vnr/`. Подходит корень домена и подпуть, например GitHub Pages проекта. Отдельные API, база сервера и секреты не требуются.

Для GitHub Pages используйте настроенный workflow **Publish Operator DNG**: GitHub → Settings → Pages → Source: **GitHub Actions**. После изменений в `main` проверки, сборка и публикация запускаются автоматически. Адрес действующей публикации указан в успешном задании `deploy` и в Settings → Pages. Включение Pages и успешную публикацию нужно подтвердить в интерфейсе GitHub.

Для проверки готовой сборки во вложенном пути, как на Pages:

```sh
PWA_TEST_ROOT=dist PWA_TEST_SUBPATH=1 node --test --test-name-pattern='complete VNR|all routes|manual calendar|PED selection' tests/browser.test.cjs
```

## Установка на iPhone и полная подготовка офлайн

1. Откройте опубликованный HTTPS-адрес в Safari и дождитесь загрузки главной страницы.
2. Нажмите «Поделиться» → «На экран Домой», подтвердите добавление. Затем запустите приложение с домашнего экрана.
3. Откройте «Справочник» → «Регламент ВНР» → «Скачать ВНР офлайн». Дождитесь сообщения **«207 страниц доступны офлайн»**. При прерывании повторите загрузку — уже сохранённые страницы используются повторно.
4. На главной откройте «Разгон» или «РИЧ» → кнопку загрузки фотографий вверху. Дождитесь подтверждения всех фотографий.
5. Закройте приложение, включите авиарежим и откройте его снова. Проверьте калькулятор, историю, страницы 1 и 207 ВНР, поиск и инструкции станции. Это обязательный ручной приёмочный шаг на вашем устройстве.

До предварительного скачивания полный ВНР и все фотографии офлайн не гарантируются: просмотренные материалы кэшируются, остальные нужно загрузить кнопками. Браузер может удалить данные сайта при очистке хранилища; история хранится локально на этом устройстве.

## Обновления

Новая версия оболочки устанавливается Service Worker; скачанные страницы и фотографии не удаляются при обновлении оболочки. При разработке следующего выпуска меняйте согласованно APP_VERSION, имя кэша оболочки и параметры версий ресурсов. Перед обновлением проверяйте `npm run check`, тесты и новую сборку.
